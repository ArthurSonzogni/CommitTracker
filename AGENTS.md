# AGENTS.md

This file provides guidance to AI coding agents (Claude Code, Codex, Cursor, Copilot, Gemini, ...) when working with code in this repository.

## What this is

CommitTracker (https://chrome-commit-tracker.arthursonzogni.com/) is a static
Nuxt 4 / Vue 3 site (`ssr: false`, client-only rendering) showing commit,
review, organization, treemap, fuzz-test, CVE and community-graph statistics
for Chromium and related repositories. Charts are hand-written with d3 modules,
and the UI kit lives in `components/ui/` (no Bulma/Buefy any more).

## Commands

```bash
npm install
npm run pull-data              # Clone the data branches into public/ (needed before anything else)
npm run generate-derived-data  # Derive usernames/organizations/summaries/badges/... from public/data
npm run dev                    # Dev server (Nuxt + data server on :3001)
npm run generate               # Production static build -> .output/public
npm run test:interactions      # E2E tests against .output/public (needs google-chrome or CHROME_PATH)
```

Running a subset of the interaction tests (matches on test `name` substring):

```bash
node scripts/test-interactions.mjs .output/public "fuzz test"
# Against the running dev server instead of a build:
BASE_URL=http://localhost:3000/ node scripts/test-interactions.mjs - "fuzz test"
```

There is no linter or unit-test suite. Builds need `--max-old-space-size=8192`
(already set in the npm scripts).

## Architecture

### Code vs data

The `main` branch holds only code. All data is generated by the importer and
pushed to orphan branches of the same GitHub repo (`data`, `community-map`,
`fuzz-test`, `treemap`, `cve`, `commit_rates`, `accretion`). `pull-data.sh`
shallow-clones each into `public/<branch>/` and writes
`public/data_updated.json`. The importer's replay state for `accretion` lives
on `accretion-state`, which the site doesn't need. Everything
under `public/` except committed assets is untracked; never commit it.

Pages fetch JSON at runtime from these paths, e.g.
`/data/<repo>/emails/<email>.json`, `/data/<repo>/usernames/<user>.json`
(see `plugins/chromiumData.ts`).

### Dev server quirk

`public/` has ~150k files, which breaks Nuxt watchers and Nitro prerender
scans. So in dev (`scripts/dev.mjs`):
- Nuxt uses `public_dev/` (recreated each run with a few symlinks into
  `public/`) as its public dir.
- `scripts/data-server.mjs` serves `public/` on port 3001, and a Nitro dev
  handler in `nuxt.config.ts` proxies any request whose path exists as a file
  in `public/`. Matching is by file existence, not prefix, because some pages
  share names with data dirs (`/treemap`, `/cve/list`).
- Heavy dirs are excluded from watchers in `nuxt.config.ts`. Keep these
  exclusions when touching the config.

### Importer pipeline (`importer/`, separate `package.json`)

Run from inside `importer/` (scripts use paths like `../repositories.json5`,
`../public/...`). GitHub API access via `octokit.mjs` reads the token from
`importer/.token`, else `GITHUB_TOKEN`/`TOKEN`.

- `fetch_data.mjs` — fetch commits per repo into `public/data/<repo>/emails/`
  (raw, per-email). Uses `mailmap.json5` to merge identities and
  `parse_reviewers.mjs` for reviewers.
- `derive_data` script — projects emails → usernames → organizations,
  summaries, commits-per-hour, badges. Run by `generate-derived-data.sh`,
  which also runs `scripts/compact-treemap.mjs`, `derive-developers.mjs`,
  `derive-highlights.mjs`.
- `clean-derived-data.sh` strips derived files back to `emails/` +
  `emails.json` before pushing the `data` branch (only raw data is stored).
- `treemap.mjs` (config in `treemap/*.yaml`), `fuzz-test.mjs`, `cve.mjs`,
  `commit_rates.mjs` produce their respective branches.
- `accretion.mjs <dirname>` replays the first-parent history like
  `git blame`, incrementally from `public/accretion/<dirname>/state.bin.gz`,
  and writes the lines alive per year, directory and developer.
- `graph.mjs` drives the C++ generator in `graph/` (CMake, OpenMP; build to
  `graph/build`) to produce community maps. It is incremental: graphs are
  only regenerated when inputs/generator change (`GRAPH_FORCE=1` to force;
  `node graph.mjs [repository] [time]` to restrict).

`repositories.json5` is the single list of tracked repositories (name,
dirname, color, GitHub owner/repo, optional `cone` subdirectory + `parent`,
`reviewers`, `treemap` flags), shared by the importer and the site.

### CI (`.github/workflows/`)

- `importer.yaml` — weekday cron; commits daily, and one other module per
  weekday (treemap Mon, fuzz Tue, commit rates Wed, CVE Thu, graph Fri).
  Each module is a composite action in `.github/actions/<module>/` that
  pushes its data branch.
- `cd.yaml` — on push to `main` or importer completion: pull data, derive,
  `generate`, run interaction tests, deploy `.output/public` to GitHub Pages
  as an artifact (the `gh-pages` branch is no longer used).

### Site structure notes

- `utils/site-pages.json` lists pages (path, label, icon, description) used by
  navigation/search (`composables/useSiteSearch.ts`) and `scripts/static-meta.mjs`
  (post-`generate` per-page meta). Update it when adding a page.
- `modules/mdi-subset.ts` subsets Material Design Icons in production by
  scanning source string tokens for `mdi` icon names; an icon name built
  dynamically from fragments will be missing from the build (an interaction
  test checks for missing icons).
- Theme (light/dark) is via `data-theme` on `<html>` and CSS tokens in
  `assets/css/theme.css`.
